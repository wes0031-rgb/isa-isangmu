3 AI Search 인덱스 설계

하나의 통합 인덱스 + source_type 디스크리미네이터 패턴.

왜 인덱스 1개로?

사용자 질문 하나에 법조항·절차·영상이 동시에 필요. 인덱스 3개면 호출 3번 + 점수 정규화 따로. 하나로 통합하면 top=12 한 방 + 색깔별 분리는 source_type 필터로 처리.

10 발표 Q&A 대비

Q. 왜 Indexer 안 쓰고 Push 방식?

데이터 소스가 다양(공공API·웹크롤링·YouTube)하고 임베딩·청킹을 코드로 제어해야 해서. ingestion이 git에 있어 재현 가능, 1982 청크 모두 수동 검증.

Q. 왜 GPT-4o를 두 번 호출?

사실 추출 / 의미 해석 역할 분리. 사이의 위험 판정은 결정론적 파이썬 함수 → AI 윤리 책임성. 각 호출 단순해져 토큰 절감 + 디버깅 용이.

Q. RAG가 hallucination 100% 막나?

아니요. 다만 ① 프롬프트 ② 스키마 ③ 후처리 3중 방어 + Citation 강제 + Golden Query 평가로 발생률을 객관 측정·억제.

Q. Custom 모델이 LLM보다 정확한가?

고정 위치 필드(고유번호·면적)는 99.5%로 LLM 압승. 하지만 가변·추론 필드(이름·위험 판정)는 LLM이 우세. 그래서 하이브리드.

Q. 평가는 누가 만들었나?

30개 시나리오 + 정답 라벨을 직접 작성 (`golden_queries.json`). 평가 스크립트가 자동 채점 → `evaluation_report.json` 출력.

Q. Azure가 죽으면?

3단 폴백: ① Azure OpenAI ② json_object 모드 ③ regex/local search. 사용자에겐 fallback 모드 표시.
